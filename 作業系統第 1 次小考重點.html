一、考古題逐題解答

先自己默寫,再點開對答案。

1(a) Process 與 Thread 的差異 5%
  • Process 是執行中的程式,擁有獨立的 address space 與資源。
  • Thread 是 CPU 使用的基本單位,同一 process 內的 threads 共用 code、data、open files。
  • 每個 thread 各自有 thread ID、program counter、register set、stack。
  • Thread 的建立與 context switch 成本遠低於 process(Solaris:建立約慢 30 倍,切換約慢 5 倍)。
1(b) IPC 的兩種基本模型 5%

Shared memory(共享記憶體)與 Message passing(訊息傳遞)。

1(c) 多執行緒程式設計的好處 5%
  1. Responsiveness:部分 thread 被 block 或做長時間工作時,程式仍可回應使用者。
  2. Resource sharing:thread 預設共用所屬 process 的記憶體與資源。
  3. Economy:建立與切換成本低。
  4. Scalability:可在多處理器上平行執行。
1(d) 什麼是 PCB 5%

Process Control Block:OS 為每個 process 記錄資訊的資料結構,context switch 時存取的就是它。內容:

  • Process state
  • Program counter
  • CPU registers
  • CPU scheduling information
  • Memory-management information
  • Accounting information
  • I/O status information
1(e) 三種 multithreading model 5%
模型重點例子
Many-to-One多個 user thread 對應一個 kernel threadSolaris Green Threads
One-to-One每個 user thread 對應一個 kernel threadWindows、Linux
Many-to-Many多個 user thread 對應多個 kernel threadSolaris 9 之前

另有 Two-level model:M:M 加上可把 user thread 綁定特定 kernel thread。

1(f) 多核心程式設計的挑戰 5%
  • Dividing activities:切分工作
  • Balance:平衡負載
  • Data splitting:資料切分
  • Data dependency:資料相依
  • Testing and debugging:測試與除錯
2. Process 狀態轉換圖 10%
  • new → ready:admitted
  • ready → running:scheduler dispatch
  • running → ready:interrupt
  • running → waiting:I/O or event wait
  • waiting → ready:I/O or event completion
  • running → terminated:exit

圖中 interrupt 的箭頭方向是 running → ready。你手寫的圖那條沒標 interrupt,考試要補上。

Medium-term 在簡報裡只有圖,文字說明依課本補充。

4. Virtual machine 的主要優點 10%
  • 對 OS 設計者:可在 VM 裡開發與測試系統,不會干擾正在運作的系統。
  • 對使用者:同一台硬體可同時跑多個不同的 OS,彼此隔離保護;也能把多個低負載系統整合到較少的機器上。
5. 傳參數給 OS 的三種方法 10%
  1. 放在 registers:最簡單,但參數可能比 register 多。
  2. 放在記憶體的 block / table,再把位址放進 register(Linux、Solaris 採用)。
  3. 程式把參數 push 到 stack,OS 再 pop 出來。

後兩種不限制參數的數量與長度。

6. Kernel 做 context switch 的動作 10%
  1. 把舊 process 目前的狀態(registers、program counter 等)存進它的 PCB。
  2. 從新 process 的 PCB 載入先前存的狀態。
  3. 新 process 從上次中斷的地方繼續執行。

切換期間系統不做有用的工作,是純 overhead,時間長短取決於硬體支援。

7. Producer-Consumer Problem 20%

(a) 是什麼

Producer 產生資訊,Consumer 消耗資訊,兩者透過共用的 buffer 溝通。Buffer 分 unbounded(無大小限制)與 bounded(固定大小)。Buffer 滿時 producer 要等,空時 consumer 要等。

(b) Pseudocode(bounded buffer)

#define BUFFER_SIZE 10
item buffer[BUFFER_SIZE];
int in = 0, out = 0;

// Producer
while (true) {
    /* produce an item */
    while (((in + 1) % BUFFER_SIZE) == out)
        ;   /* buffer full, do nothing */
    buffer[in] = item;
    in = (in + 1) % BUFFER_SIZE;
}

// Consumer
while (true) {
    while (in == out)
        ;   /* buffer empty, do nothing */
    item = buffer[out];
    out = (out + 1) % BUFFER_SIZE;
    /* consume the item */
}

此解法正確,但只能使用 BUFFER_SIZE−1 個格子。

(c) 屬於哪種 IPC

Shared memory(簡報的解法即為 shared-memory solution)。

二、這次沒考、但很可能出現

ch03 Process

  • Process 在記憶體中包含:program counter、stack、data section(另有 text/code)。
  • 三種 queue:job queue、ready queue、device queues。
  • 建立:fork() 複製子 process,exec() 用新程式取代記憶體空間,parent 用 wait() 等 child。
  • 終止:exit、abort;parent 結束時 child 也被終止稱為 cascading termination。
  • Cooperating processes 的原因:information sharing、computation speedup、modularity、convenience。
  • Message passing:
    • Direct(指名對方)vs Indirect(透過 mailbox / port)
    • Blocking(同步)vs Non-blocking(非同步)
    • Buffering:zero capacity(rendezvous)、bounded、unbounded
  • Socket = IP + port;RPC 用 stub 與 marshalling。

ch02 系統結構

  • OS services:UI、program execution、I/O、file system、communication、error detection、resource allocation、accounting、protection and security。
  • 為什麼用 API 而不直接呼叫 system call:可攜性、比較簡單好用、隱藏細節(簡報有問但沒答,此為課本答案)。
  • 三大 API:Win32、POSIX、Java API;printf() 會呼叫 write() system call。
  • System call 六類:process control、file management、device management、information maintenance、communications、protection。
  • Policy(做什麼)vs Mechanism(怎麼做),分離才有彈性。
  • OS 結構:Simple(MS-DOS)、Layered、Microkernel、Modules。
    • Microkernel 優點:容易擴充、容易移植、更可靠、更安全。
    • Microkernel 缺點:user space 與 kernel space 溝通有效能 overhead。
  • Para-virtualization:guest 需修改才能執行。
  • Bootstrap loader 存在 ROM / firmware,負責找到 kernel、載入並啟動。

ch04 Thread

  • User threads(由 library 管理,不需 kernel 支援)vs Kernel threads(由 OS 管理)。
  • 三個 library:Pthreads、Win32、Java。
  • Threading issues:fork() / exec() 語意、thread cancellation、signal handling、thread pools、thread-specific data、scheduler activations。
  • Thread cancellation:asynchronous(立即終止)vs deferred(目標 thread 定期檢查)。
  • Thread pool 優點:用現成 thread 比新建快,且能限制 thread 總數。
  • Linux 用 clone() 建立 thread,不區分 process 與 thread,統稱 task。
